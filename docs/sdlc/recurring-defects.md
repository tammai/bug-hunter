# Recurring defects

One line per defect: what it looks like, then the severity.

- A record of an outside action (an issue filed, a message sent) written after the action with no write check beforehand, no fsync and no fallback, so a failed write repeats the action next run: high
- A target repo copied with `cp -R` (worktree `.git` file, `.venv` paths, `origin`, symlinks) so code run "in the copy" changes the original: high
- Text anyone can write (issue titles, repo files, agent output) passed to an agent that holds the owner's credentials, with no "data, never instructions" rule and no credential isolation: high
- Folder or key names built by joining parts with a character the parts may contain (`owner-repo`), so two inputs collide: high
- A CLI error path that ends in a Python traceback instead of a one-line message (missing tool, `str.isdigit()` on `²`, a directory where a file is expected, non-UTF-8 names): high
- Porcelain git output (`git diff`, `git log`) parsed or applied without pinning the options the user's config can change: medium
- A shell step built from a name the target controls (a folder, a file) and quoted with double quotes, or not filtered for quotes, `$`, backticks, backslashes and a leading `-`: high
- Agent isolation done by moving `HOME` only, missing variables already expanded to the real home, Java's `user.home`, JVM option variables and active virtualenvs: high
- `eval "$(cmd)"` used for a safety setup step, so a failed or empty `cmd` runs the rest unprotected: high
- A tool setting kept pointed at the owner's real folders (runtime managers, SDKs) while the tool can auto-install into them from a repo file: high
- Deciding "is this a secret?" from the shape of free text (`NAME = value`, long base64) instead of checking against the values actually found: high (it trades leaks for rejected findings each way it is tuned)
- A placeholder or redaction test that matches a substring, so a partly masked real value (`Pass<redacted>`, `AKIA…xxxx`) counts as a placeholder: high
- A "looks like a path" or "looks like code" exemption that also matches real secret alphabets (base64 values starting with `/`, JWTs with dots): high
- A multi-line block parser (PEM body) that enters block mode on a header mention, or never leaves it, so the rest of the file is skipped: high
- Log redaction that matches secret words in raw text without first decoding `%xx` (nested), `\u`, `\x` and `&#` escapes, so `%2574oken` or `password` is logged: high
- A fallback path (malformed input, parse error, a body that was withheld) that logs raw input under a weaker check than the main path: high
- A test's fake CLI (a `#!` script named `gh`) that the OS can't run, so the code under test finds the real, logged-in tool on PATH and acts for real (Windows filed real issues): high
- "Logged out" by pointing a CLI at an empty config folder while the OS keyring (Windows Credential Manager, macOS Keychain) still holds its token; override the token variable instead: high
- A capability check that names `os.replace` (or another alias) in `os.supports_dir_fd`, which only lists `os.rename`, so the safe descriptor path silently turns off and the fallback passes the same tests: high
- On Windows, environment handling built on `os.environ` (names uppercased) feeding a case-sensitive shell, so `unset NAME` misses `Name` and mixed-case secrets survive: high
- A log of request bodies that redacts by text pattern instead of parsing the body's own shape (JSON, ndjson, form, multipart), so secret-named keys with object values, multi-line parts or bracketed names (`user[password]`) leak: high
- Credentials loaded from a config file and sent as HTTP headers without checking them first, so a value with a line break or a non-Latin-1 character raises inside the HTTP library and its traceback prints the token: high
- A proxy that relays a server's responses unchanged to an agent that must not see the credentials it added, so an echoing endpoint (debug page, `Location`) hands them back: high
- A read-only guard that checks only the request method, so `X-HTTP-Method-Override` or `_method` turns an allowed GET into a write: high
- A shell step that sets a variable as a command prefix (`BASE=x curl "$BASE"`), which the same command's own expansion never sees, or that a later setup step unsets (`isolate.py` drops `*AUTH*`): high
- Two matchers for one value (a leak scan and a masker) with separate pattern sets or separate case and Unicode rules (bytes vs str, `re.I` folding K and ſ, `\w` vs ASCII), so one hides what the other reveals: high
- Masking that matches secrets case-insensitively, or a dotless host name (`uat`) without its scheme or port, so ordinary response text is mangled and hunters report the proxy's damage as the target's bug (a dotted host inside a longer word is masked on purpose: the masker uses the leak scan's patterns): medium
- Stopping a background job by the PID `$!` gave, when `$!` can be a subshell (`cmd && prog &`, `( … ) &`): killing it leaves `prog` running under PID 1; stop the whole process tree, recorded while the subshell lives: high
- A `cd` chained into a backgrounded `&&` list (`cd copy && … & echo $! > f`): the `cd` runs only in the background job, so the next relative write lands in the starting folder (the target repo): high
- `shutil.which` (or any PATH lookup) run from inside a target repo on Windows without `NoDefaultCurrentDirectoryInExePath`: a `ps.bat` the repo commits runs unisolated; a test that removes the variable must match its name case-insensitively: critical
- `Path.resolve()`, `is_file()` or `open()` on a path an agent or target wrote before checking it lies inside the repo: a `\\host\share` path makes Windows authenticate to that host: high
- An error or problem line that echoes the input it rejected, when that input can be a secret (a citation, a header, a config line): name the item by position instead: high
- A numeric field read from an agent- or target-written file with `isdigit()` and `int()` but no length or range bound, so a huge value raises (`OverflowError`, `ValueError`) instead of being skipped: high
- Commands and outputs recovered by parsing free-form markdown (heredocs, fences, prompts, prose) instead of having the producer write them as structured data and rendering the markdown from it: high
- Masks for several targets (or kinds of secret) applied one after the other, so one pass rewrites part of a value or address that another pass would have matched whole, leaving the rest unmasked; build one pass over all of them, longest first: high
- A step that re-checks a finding already verified (a re-run, a classifier) treats a refused, unreachable or timed-out run as a verdict and drops the finding; a run that didn't happen is an environment result, kept for a retry: high
- A leak scan (or masker) that matches a host or secret with word-boundary checks on partly decoded text: an undecoded escape (\n, \x2F, an ANSI code), an underscore or a letter of another script before the value blocks the match; decode every layer to a fixed point and match without a left boundary: high
- An encoding test table that only rewrites one character class (slashes) and so cannot see a whole class of escapes before the value; vary what stands right before it (each escape, _, other scripts, digits): medium
- A test runner (browser, replay) that reports a run the infrastructure broke (no browser, a proxy refusal, a network error, a timeout) as a failing test, so it counts as proof of a bug; report it as not run: high
- A recursive delete or chmod that checks a path is a folder and acts on the path later (or retries a failed step by full path from an error hook), so code still running in the folder can swap a link in and the walk leaves it; open each folder with `O_NOFOLLOW` relative to its parent's handle and do every step through that handle: high
- Cleanup that stops at the first entry it can't remove, or deletes its marker before the rest, so a secret file survives or a later sweep can't find the leftover folder: high
- A test written for a guard that passes with the guard removed (the swap lands before the check, or an earlier error skips the code under test): medium
- A check of a folder untrusted code can write that runs a tool reading that folder's own config (`git status` in a base whose `.git/config` a repro could change) before comparing, so a planted `core.fsmonitor` or clean filter runs before the refusal; compare the files first, in plain code, and refuse command-naming keys outright: high
- An integrity check built on `git status` (or any tool's view) of a tree untrusted code can write: status names a path, not what it holds, and hides what git doesn't track (a `.git` planted in a subfolder, a pipe, an empty folder, a submodule's files), so a change that keeps the listing passes; walk the tree yourself and hash what the listing names by type, mode and content, length-framed: high
- Code that hashes or lists the paths a tool printed and assumes each is a file or missing: a path can be a folder, or sit under a folder turned into a file (`NotADirectoryError`), and one unhandled type refuses a valid input: high
- A script that runs `git -C <repo>` with the caller's environment, so `GIT_DIR`, `GIT_WORK_TREE` or `GIT_INDEX_FILE` set by a hook or alias sends the command (a clone, a config write, a remote removal) to another repo; drop what `git rev-parse --local-env-vars` lists: high
- A cache built from secrets (a masker, a matcher) that is checked and rebuilt outside the lock that swaps the secrets in, or rebuilt from only the newest values, so a response sent with a new or replaced token is masked by a stale cache: high
- A retry or second upstream send (after a 401, a redirect, a refresh) that skips the budget and rate accounting the first send went through: high
- A rule that infers "this request reached the target" from the absence of a log note, so a new note on forwarded lines makes budget restarts or clean-up lists undercount; log an explicit field: high
- File names turned into bytes with `str.encode()` instead of `os.fsencode`, so a non-UTF-8 name (a Latin-1 branch on Linux) raises `UnicodeEncodeError`, a `ValueError` an `except OSError` doesn't catch: high
- A record kept across runs whose facts are read only from its first sighting, while dedupe drops the later, truer copy (a secret since committed, an advisory rated up), so a blocking finding reads low; append what later runs learn and rank on the most severe: high
- "Not produced again, so fixed" without checking the producer ran and could see it (a failed or skipped audit, a lockfile deleted only in the working tree, a secret still in git history): high
- A target-controlled name (file, folder, lockfile) written into a line-structured record or report without escaping control characters, so a newline forges a heading or an evidence line the parser reads first: high
- A left boundary or lookbehind added to a leak or host matcher to cut over-refusal or scan cost, so a prefix (another scheme, a dot, a digit, an undecoded escape) now hides the value the matcher must refuse; anchor at a run's start and check the run's end instead: high
- A decode check that runs on str after `unquote`, so bytes that aren't UTF-8 (overlong forms such as `%c0%ae`, `%e0%80%ae`) become U+FFFD and slip past a dot or separator check; check each decode round as bytes: high
- An error or warning line that prints untrusted text (a registry, a draft, a parser's message quoting either) without escaping control and bidi characters or bounding its length, so a newline forges another `error:` line or an escape sequence rewrites the terminal: high
- A git call on a target repo that trusts a config-level guard (`protocol.allow`, filter blanking by `GIT_CONFIG_COUNT`, `GIT_NO_LAZY_FETCH`) that the repo's own config can override (`protocol.file.allow=always`) or an older git silently ignores; use `GIT_ALLOW_PROTOCOL`, check the git version, and fail closed: high
- "git found nothing in history" read as "never committed" when git couldn't see all history (a shallow, partial or grafted clone, replace refs, a timeout); answer "can't say" and make it a gap: high
- A value cleaner that splits a list on separators before stripping credentials, so a password containing the separator (or digits that read as a port) leaves a fragment: high
- An exemption chosen from a variable's name alone, without checking what its value is (`BASH_FUNC_` with a non-function value): high
- An external scanner's JSON read without its exit code: a failed run (no offline database, a file it can't parse) still prints an empty result that reads as clean; accept only the exit codes that mean it scanned: high
- A scanner run on the target repo that also reads the repo's own config (`osv-scanner.toml` ignore entries and the like), so the target can hide its own findings; pass an empty config the plugin owns: high
- A guard on agent output keyed on one word the agent can leave out or disguise (a tool's name, while its rule ids, look-alike letters or zero-width characters pass); key it on the run's own data (ids, `path:line`) over NFKC-folded text: high
- An unrated or unknown-severity advisory defaulting to a severity that doesn't block (medium), so a malicious or unrated package reads Safe to deploy; unrated is high, `MAL-` is critical, take the worst rating: high
- A stored finding moved to fixed because its key (an advisory id the matcher doesn't recognise) can't be matched to this run's output; with no usable key, keep it open while its package is still reported: high
