# Security checklist: Rust backends (Actix, Axum, Rocket)

Use with the generic and PII checklists. Safe Rust rules out most memory bugs, so the findings are in `unsafe`, in logic, and in the web layer.

## Memory safety and panics
- **`unsafe` on input data:** `unsafe { }` blocks, `get_unchecked`, `from_utf8_unchecked`, `slice::from_raw_parts`, `ptr::copy`, `transmute`, `set_len` or `Vec::from_raw_parts` where the length, index or bytes come from a request, a file or a network frame. Check each one for a bounds or validity guarantee in the line above it. CWE-787, CWE-125, CWE-416.
- **FFI boundaries:** `extern "C"` calls and `CString::new(user_input).unwrap()`, C libraries fed lengths from input, `Send`/`Sync` implemented by hand with `unsafe impl` on types holding raw pointers or interior mutability. CWE-119, CWE-362.
- **`unwrap()`, `expect()` and indexing on request input:** `body.get("x").unwrap()`, `s.parse::<u32>().unwrap()`, `vec[idx]` with a client index, `&s[a..b]` slicing a `String` at client offsets (panics on non-char boundaries), integer `as` casts. One bad request panics the handler; with a `panic = "abort"` profile or a panic inside a shared lock, it takes the service down or poisons the `Mutex`. CWE-248, CWE-400, CWE-703.
- **Integer overflow:** arithmetic on sizes, prices, quantities or balances with plain `+`, `*` and `as` casts; release builds wrap silently unless `overflow-checks = true`. Look for `checked_add`, `saturating_*`, or their absence near money and allocation sizes. CWE-190.
- **Unbounded allocation:** `Vec::with_capacity(n)` or `vec![0; n]` with a client-sent `n`, bodies read with no limit (`web::PayloadConfig`, `JsonConfig::limit`, `DefaultBodyLimit` removed or `usize::MAX`, `to_bytes(body, usize::MAX)`), and decompression with no cap. CWE-770.

## Injection and external calls
- **`sqlx` and `diesel` raw queries:** `sqlx::query(&format!("... {}", input))`, `query_as` with a built `String`, `diesel::sql_query(format!(...))`, `sea_orm` `Statement::from_string` with input. `query!` macros and `.bind()` are safe; column names, `ORDER BY` and `LIMIT` pieces from input are not. CWE-89.
- **`std::process::Command` with input:** `Command::new("sh").arg("-c").arg(user_input)`, `Command::new(user_value)`, or user-controlled arguments starting with `-` (option injection). A fixed program with an argument list is fine. CWE-78.
- **Path traversal:** `PathBuf::join(user_input)` or `Path::new(base).join(name)` then `File::open`, `fs::read`, `NamedFile::open`, `ServeDir`, `tokio::fs`. `join` with an absolute path *replaces* the base (`/etc/passwd`), and `..` segments are not removed. Canonicalize and check `starts_with(base)`, and reject absolute or `..` components. Also `actix_files::Files` with `show_files_listing()`. CWE-22.
- **Archive extraction:** `zip` or `tar` entries unpacked at `dest.join(entry.name())` with no check (zip slip), and `tar` `unpack` on untrusted archives. CWE-22.
- **SSRF with `reqwest`:** `reqwest::get(url)`, `Client::get(&input)`, webhook or image-fetch features with a user URL, no allow-list, no block on private and metadata addresses, automatic redirects (`redirect::Policy::default()` follows 10), and no `timeout`. CWE-918, CWE-400.
- **Templates:** `askama` with `|safe` or `maud` `PreEscaped(input)`, `tera` with `autoescape` disabled for a template extension, or HTML built with `format!` and returned as `text/html`. CWE-79.

## Authentication and authorization
- **Missing extractor or guard:** a handler without an auth extractor (Actix middleware or `FromRequest` user type, Axum `Extension<User>`/ custom extractor / `route_layer`, Rocket request guard) while sibling handlers have one; an Axum `Router::layer(auth)` applied *before* later `.route(...)` calls, so those routes sit outside it (layers cover only routes added before them); `nest` or `merge` of a router that skipped the layer. CWE-862.
- **Optional auth treated as required:** an extractor wrapped in `Option<User>` or `Result<User, _>` where `None` or `Err` falls through to the privileged path, `unwrap_or_default()` on a role, or a Rocket `Outcome::Forward` leading to an unguarded fallback route. CWE-306, CWE-863.
- **IDOR:** `Path<Uuid>` or `Path<i64>` ids passed to `sqlx` or diesel `find` with no `AND owner_id = $2` taken from the authenticated user. Check the repository layer. CWE-639.
- **`serde` accepting more than intended:** request structs for authz-relevant data (roles, permissions, ownership, prices, `is_admin`) with no `#[serde(deny_unknown_fields)]`, `#[serde(default)]` on security fields, `#[serde(flatten)]` into maps, `Option<T>` fields that skip validation when `None`, or a single struct used for both input and the stored model so the client sets `id`, `role` or `owner_id`. Use a separate input type. CWE-915, CWE-20.
- **JWT:** `jsonwebtoken::decode` with `Validation::default()` but no pinned algorithm (`Validation::new(Algorithm::HS256)`), `validate_exp = false`, `insecure_disable_signature_validation`, or `dangerous_unsafe_decode` results used for access, plus a hard-coded `EncodingKey::from_secret(b"secret")`. CWE-347, CWE-798.
- **Weak randomness for tokens:** `rand::thread_rng()` is a CSPRNG in current `rand`, so flag the weaker generators instead: `SmallRng`, `StdRng::seed_from_u64(...)`, `fastrand`, `oorandom` or time-seeded generators used for session ids, reset tokens, API keys, OTPs or nonces. Use `OsRng` (or `rand::rng()` / `ThreadRng` in `rand` 0.9 and later) and at least 128 bits. CWE-338, CWE-330.
- **Password and secret handling:** `sha2`, `md5` or `blake3` hashing passwords instead of `argon2`, `bcrypt` or `scrypt`; `==` on tokens, MACs or keys instead of `subtle::ConstantTimeEq` or `hmac::verify`. CWE-916, CWE-208.
- **Cookies and sessions:** `actix-session` / `tower-sessions` / Rocket private cookies with a hard-coded key (`Key::from(b"...")`), `Cookie::build` without `secure(true)`, `http_only(true)`, `same_site(...)`, sessions never expiring or not rotated at login; no CSRF check on cookie-authenticated writes. CWE-614, CWE-1004, CWE-384, CWE-352.

## Transport, configuration and logging
- **Disabled TLS checks:** `danger_accept_invalid_certs(true)`, `danger_accept_invalid_hostnames(true)`, `native-tls` or `rustls` with a custom verifier that accepts everything, or `http://` URLs for services that carry credentials. CWE-295, CWE-319.
- **CORS:** `Cors::permissive()` or `actix_cors::Cors::default().allow_any_origin()`, `tower_http::cors::CorsLayer::permissive()`, or `allow_origin(Any)` combined with `allow_credentials(true)`; origins reflected from the request. CWE-942.
- **Secrets and config:** `const SECRET: &str = "..."` or `env!("SECRET")` baked into the binary, `.env` committed, `dotenv` defaults such as `unwrap_or("changeme")`, and a Rocket `secret_key` written into `Rocket.toml` in the repository. CWE-798, CWE-1188.
- **Error and log exposure:** `HttpResponse::InternalServerError().body(e.to_string())`, `impl IntoResponse` returning `{:?}` of a database error, `#[derive(Debug)]` structs holding passwords or tokens printed with `{:?}` in `tracing::info!`/`log::debug!`, `tracing` spans recording headers or bodies. Wrap secrets in `secrecy::Secret` or a type whose `Debug` redacts. CWE-209, CWE-532.
- **Concurrency:** `static mut`, check-then-act across `await` points on balances or stock with a `Mutex` locked separately for the check and the write, `tokio::spawn` tasks that drop errors (`let _ = ...`) from auth or audit steps. CWE-362, CWE-252.
