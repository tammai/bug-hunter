# Security checklist: Python backends (Django, Flask, FastAPI)

Use with the generic and PII checklists.

## Injection and code execution
- **Raw SQL with formatting:** `cursor.execute(f"... {x}")`, `"..." % x`, `.format()` or `+` passed to `execute`, `engine.execute`, `text(f"...")` in SQLAlchemy, `Model.objects.raw(f"...")`, `.extra(where=[f"..."])`, `RawSQL(f"...")`, `connection.cursor()`. Parameterized forms (`execute(sql, [x])`, `text(":x")` with bind params) are safe; table, column and `order_by` names from input are not. Also `order_by(request.GET["sort"])` and `**request.GET` passed to `filter()` (lookup injection). CWE-89.
- **Unsafe deserialization:** `pickle.loads`, `pickle.load`, `cPickle`, `marshal.loads`, `shelve`, `dill`, `jsonpickle.decode`, `yaml.load(x)` without `SafeLoader` (or `yaml.unsafe_load`), `torch.load` on untrusted files, and Django's `PickleSerializer` for sessions, or cached/queued values another party can write. CWE-502.
- **Dynamic code:** `eval(`, `exec(`, `compile(`, `__import__(user_input)`, `importlib.import_module(name)`, `getattr(module, name)()` with a name from the request. CWE-94, CWE-95.
- **Shell commands:** `subprocess.run/Popen/call/check_output(..., shell=True)` with a built string, `os.system`, `os.popen`, `commands.getoutput`. A list of arguments without `shell=True` avoids the shell, but an argument starting with `-` can still be read as an option by the program. CWE-78.
- **Template injection and XSS:** Jinja2 `Environment(autoescape=False)` (the default for a plain `Environment`), `render_template_string(user_input)` or `Template(user_input).render()` (server-side template injection), `|safe`, `Markup(user_input)`, Django `mark_safe(...)`, `format_html` called with pre-formatted strings, `{% autoescape off %}`, `HttpResponse(f"<p>{name}</p>")`. CWE-79, CWE-1336.
- **XML and parsers:** `xml.etree`, `xml.dom.minidom`, `lxml.etree.parse` with `resolve_entities` default on untrusted XML (XXE and entity expansion; use `defusedxml`), `zipfile.extractall` or `tarfile.extractall` on untrusted archives. CWE-611, CWE-22.
- **LDAP, header and log injection:** `ldap.search_s(f"...")`, user input placed in `response["Location"]`, other headers, or `logging.info(f"login {username}")` with newlines allowed. CWE-90, CWE-113, CWE-117.
- **Path traversal:** `open(os.path.join(BASE, name))`, `send_file(path)`, `send_from_directory` with a custom path, `FileResponse(path)`, `static` handlers. `os.path.join(base, "/etc/passwd")` discards the base, and `..` is not removed; use `os.path.realpath` plus a prefix check, or `werkzeug.utils.safe_join` and `secure_filename` for uploads. CWE-22.

## Authentication and authorization
- **Missing auth:** Django views with no `@login_required`, `LoginRequiredMixin`, `@permission_required` or `PermissionRequiredMixin`; DRF views with `permission_classes = [AllowAny]`, an empty list, or `DEFAULT_PERMISSION_CLASSES` unset (default is `AllowAny`); Flask routes with no `@login_required` or custom decorator while sibling routes have one; FastAPI endpoints with no `Depends(get_current_user)` or `Security(...)`, and routers included without `dependencies=[Depends(...)]`. CWE-862, CWE-306.
- **ORM filter missing the owner:** `Order.objects.get(pk=pk)`, `get_object_or_404(Invoice, pk=pk)`, `Model.query.get(id)`, `session.get(Model, id)`, or a DRF `queryset = Model.objects.all()` in a `ModelViewSet` with no `.filter(owner=request.user)` or `get_queryset` override. Check serializers for read and write of other users' data. CWE-639.
- **Mass assignment:** `Model(**request.POST)`, `Model(**request.data)`, `ModelForm` with `fields = "__all__"`, DRF `ModelSerializer` with `fields = "__all__"` or `exclude = [...]` that misses `is_staff`, `is_superuser`, `role`, `owner`; FastAPI/Pydantic models reused as both input and database model; `setattr(obj, k, v)` loops over input keys. CWE-915.
- **Secrets in settings:** a hard-coded `SECRET_KEY` in `settings.py`, Flask `app.secret_key = "dev"` or `SECRET_KEY = "changeme"`, JWT `secret` constants, a committed `.env`, default admin passwords in fixtures or migrations. A known `SECRET_KEY` allows forged sessions and signed cookies (and code execution with pickle serializers). CWE-798.
- **JWT:** `jwt.decode(token, options={"verify_signature": False})`, `jwt.decode(token, key)` with no `algorithms=[...]` list (older PyJWT) or with `"none"` allowed, no `exp` requirement, `python-jose` configs accepting any algorithm, tokens read with `jwt.get_unverified_claims`. CWE-347.
- **Weak randomness and hashing:** `random.random`, `random.choice`, `random.randint`, `uuid.uuid1`, `time`-seeded values for tokens, reset links, OTPs or API keys instead of `secrets.token_urlsafe` or `secrets.token_hex`; `hashlib.md5/sha1/sha256` or `PASSWORD_HASHERS` with `MD5PasswordHasher`/`UnsaltedSHA1PasswordHasher` instead of Argon2, bcrypt or PBKDF2. Token comparisons with `==` instead of `hmac.compare_digest`. CWE-338, CWE-916, CWE-208.
- **Sessions and cookies:** Flask `session` (signed but *not encrypted*: its contents are readable by the client) holding secrets or roles; `SESSION_COOKIE_SECURE`, `SESSION_COOKIE_HTTPONLY`, `SESSION_COOKIE_SAMESITE` unset or false (Django: `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE`); sessions not rotated at login (`cycle_key`), no expiry. CWE-614, CWE-1004, CWE-384.
- **CSRF disabled:** `@csrf_exempt` on state-changing views that use cookie or session auth, `CsrfViewMiddleware` removed from `MIDDLEWARE`, Flask with no `Flask-WTF` `CSRFProtect` and cookie auth, DRF `SessionAuthentication` subclass that skips `enforce_csrf`. CWE-352.

## Configuration and outbound calls
- **Debug on:** `DEBUG = True` outside tests (shows settings and tracebacks), `app.run(debug=True)` or `FLASK_DEBUG=1` (the Werkzeug console allows code execution), `debug=True` in `FastAPI(...)` or `Starlette(...)`, `ALLOWED_HOSTS = ["*"]` or empty with debug off. CWE-489, CWE-209, CWE-16.
- **Headers and TLS settings:** Django without `SECURE_SSL_REDIRECT`, `SECURE_HSTS_SECONDS`, `X_FRAME_OPTIONS`, `SECURE_CONTENT_TYPE_NOSNIFF`; `CORS_ALLOW_ALL_ORIGINS = True` or `CORS_ALLOW_CREDENTIALS = True` with a reflected origin (`django-cors-headers`, FastAPI `CORSMiddleware(allow_origins=["*"], allow_credentials=True)`, `flask-cors` with defaults). CWE-942, CWE-693.
- **`requests` without timeouts or with SSRF:** `requests.get(url)`, `httpx.get`, `urllib.request.urlopen`, `aiohttp` calls with no `timeout=` (requests has none by default: a slow server hangs the worker), a `url` from the request with no allow-list and no block on private/link-local ranges, redirects followed, `file://` accepted by `urlopen`. CWE-918, CWE-400.
- **TLS verification off:** `verify=False` in `requests`/`httpx`, `ssl._create_unverified_context()`, `ssl.CERT_NONE`, `urllib3.disable_warnings()`. CWE-295.
- **File uploads:** `request.FILES` or `UploadFile` saved with the client's filename, no size or type check (`content_type` is client-controlled), saved under `MEDIA_ROOT` or `static/` and served; `PIL.Image.open` on uploads with decompression-bomb limits disabled (`Image.MAX_IMAGE_PIXELS = None`); no `DATA_UPLOAD_MAX_MEMORY_SIZE`/`client_max_body_size`. CWE-434, CWE-770.
- **Logging and errors:** `logger.info(request.POST)`, `logging.debug(f"... {password}")`, `print(user.__dict__)`, `traceback.format_exc()` returned in a response, a bare `except: pass` around an auth or permission check that then continues. CWE-532, CWE-209, CWE-390.
- **Regex and resource limits:** `re.match` with nested quantifiers on request input (ReDoS), no pagination limit (`page_size` from input with no cap), `json.loads` or `yaml` on unbounded bodies. CWE-1333, CWE-400.
