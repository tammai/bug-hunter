# Security checklist: TypeScript

Use with the generic and PII checklists. Types are erased at compile time: a type annotation on request data checks nothing at run time. Node backend items stay in the Node checklist; this one covers what TypeScript hides or invites.

## Types that stand in for validation
- **Cast request input:** `req.body as CreateUserDto`, `<Order>req.body`, `const { role } = req.body as User`, `ctx.request.body as any`. The cast tells the compiler to trust the data; nothing checks it. Look for the same shape in handlers, tRPC or GraphQL resolvers, server actions and message-queue consumers. CWE-20.
- **`any` and `unknown` plumbing:** `any` on `req.body`, `req.query`, `event.body`, webhook payloads or `JSON.parse` output that then reaches a query, a file path, a shell call or a `redirect`. Follow the value to the sink; the compiler won't. CWE-20 (then the sink's CWE, e.g. CWE-89 or CWE-22).
- **`JSON.parse` cast to a type:** `const cfg = JSON.parse(raw) as Config`, `await res.json() as ApiUser`, `JSON.parse(localStorage.getItem(...)!)`. Missing fields, extra fields and wrong types all pass. Where the result decides access (roles, ids, prices, flags), a runtime schema is needed. CWE-20, CWE-502.
- **Type-only validation:** DTO classes, interfaces or `type` aliases for request bodies with no `zod`, `valibot`, `yup`, `io-ts`, `ajv` or `class-validator` call, or a schema defined but `.parse` never invoked (only `safeParse` with the `success` flag ignored). CWE-20.
- **Non-null `!` and optional chaining that hide absence:** `req.user!.id`, `session!.userId`, `token!` where the value can be missing for unauthenticated callers, so the code throws (a 500) or, worse, compares `undefined === undefined` and grants access. CWE-476, CWE-287.
- **Structural typing surprises:** an object with extra properties assigned to a narrower type is allowed, so `{ ...body }` passed to `repo.update(id, body)` still carries `role`, `isAdmin` or `ownerId`. Excess-property checks apply only to fresh object literals. CWE-915.
- **Enums and unions trusted from input:** `status as OrderStatus`, `role as Role`, a `switch` over a string union with no `default` that rejects unknown values, or a numeric `enum` where any number is accepted (numeric enums allow arbitrary values). The cast makes the value look checked. CWE-20.
- **Index access with input keys:** `config[req.query.key]`, `handlers[body.action]()`, `obj[key] = value` with `key: string` from input, `Record<string, ...>` lookups that reach `__proto__`, `constructor` or inherited keys. CWE-1321, CWE-470.

## Suppressed checks
- **`// @ts-ignore`, `// @ts-expect-error`, `// @ts-nocheck`** over auth, session, crypto or validation code, or over a call whose types disagree because a guard returns `boolean | undefined`. Read what the compiler was complaining about. CWE-754.
- **Weakened compiler settings:** `strict: false`, `strictNullChecks: false`, `noImplicitAny: false`, `skipLibCheck` hiding bad types in a security package, or `useUnknownInCatchVariables` off so `catch (e)` reads `e.message` unchecked. These turn off the checks that catch missing-value bugs. CWE-754.
- **Unsafe type guards:** user-defined `function isAdmin(u): u is Admin` that returns `true` from a weak test (`'role' in u`, `typeof u === 'object'`), assertion functions that do nothing, or `satisfies` / `as const` used as if they validated. CWE-863.
- **ESLint disables** such as `@typescript-eslint/no-explicit-any`, `no-unsafe-assignment`, `no-floating-promises` switched off near auth code. An un-awaited `checkPermission(...)` returns a promise, which is always truthy. CWE-863, CWE-252.

## Frameworks and decorators
- **NestJS `ValidationPipe`:** not registered globally (`app.useGlobalPipes`) or per controller, or registered without `whitelist: true` and `forbidNonWhitelisted: true`, so extra fields pass into services (mass assignment). Also `transform: true` with `enableImplicitConversion` turning strings into numbers or booleans unexpectedly. CWE-915, CWE-20.
- **DTO decorators:** `class-validator` DTOs with fields that have no decorator (not validated and, with `whitelist`, silently dropped or, without it, passed through), `@IsOptional()` on required security fields, `@Type(() => Object)`, or `@ValidateNested()` missing on nested objects. CWE-20.
- **Guards and decorators on the wrong layer:** `@UseGuards(AuthGuard)` on some controller methods and not others, a custom `@Roles()` decorator that nothing reads because `RolesGuard` isn't registered, `@Public()` metadata inherited by accident. Check the guard is applied and that it returns `false` (not `true`) when metadata is absent. CWE-862, CWE-863.
- **TypeORM / Prisma typed query helpers:** `where: req.body` or `where: { ...filter }` with an object from input (operator and relation injection such as `{ id: { not: 0 } }` in Prisma, `FindOperator` shapes in TypeORM), `repo.query` or `$queryRawUnsafe` with template strings even though the rest of the code is typed. CWE-89, CWE-943.
- **`class-transformer`:** `plainToInstance(User, body)` with no `excludeExtraneousValues`, and `@Exclude()` / `@Expose()` missing on password hashes and tokens in response classes, so `serialize` leaks them. CWE-200, CWE-915.
- **Generated clients and shared types:** an OpenAPI or GraphQL codegen type used as proof the server validates, or frontend code that relies on `readonly` / required fields for authorization. The server must still check. CWE-602.
